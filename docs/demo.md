# 演示说明：约 5–8 分钟

演示前运行 Docker，打开 http://127.0.0.1:19082，管理员确认知识库已索引。所有姓名、商品和订单是项目生成的虚构数据。若模型刚启动，首问需要加载权重；请预热一次。

1. **知识有依据**：点击“客户”登录，问“栖光阅读灯需要充电吗？”。展示“不含内置电池、不支持无线充电”与来源标题/段落；再问“云屿保温杯保证保温多少小时？”，说明系统不编造未承诺参数。
2. **订单来自业务系统**：查询 `ZS20261030001`，展示商品、金额和签收状态。查询另一客户的 `ZS20261030003`，应显示未查询到本人订单，而不是透露买家信息。
3. **AI 生成草稿**：输入“我要为订单 ZS20261030001 申请退货退款，商品未使用，包装完好”。出现待确认草稿时说明：尚未创建工单、更未批准退款。点击确认创建，跳转或进入“我的工单”查看新工单。
4. **人工接续**：退出，点击“客服”登录，打开同一工单，接单为“处理中”，填写“请补充包装及配件情况”改为“待补充”。再切客户补充材料；工单回到处理中。客服填写处理结果并设为已解决，客户确认关闭。
5. **知识和运营管理**：管理员登录，查看知识片段数、索引状态、商品维护、审计记录。新增一份 UTF-8 MD 资料可按需关联商品，再建索引；先停用旧资料再发布替代版本。
6. **工程证据**：打开测试报告，说明 H2/PostgreSQL 回归、真实模型有限用例、前端流式解析、并发幂等、备份恢复和本机 Docker 部署。最后展示交付源码与迁移脚本。

备用演示：模型服务不可用时从“我的订单”直接点击“申请售后 / 咨询”，手动建单并展示完整客服流程。此模式必须明确说是降级路径，不能作为真实模型效果展示。

面试讲解重点：为什么订单归属由后端判断；为什么模型先生成草稿；为什么请求幂等和版本号解决的是两类问题；为什么保留引用快照；小知识库为何先选择关系库存向量并在 Java 中计算；扩展到多实例时需要哪些变化。
