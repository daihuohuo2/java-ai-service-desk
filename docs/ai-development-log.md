## 用户任务与实现约束

项目需求是完成 Java＋AI 智能客服与售后工单应用，提供前后端、测试和部署交付材料。初期没有目标服务器，先做本机部署验收与可迁移包；另提供适合 Java 初学者的源码阅读指南。

核心设计提示要求归纳：Java 负责业务及授权，使用本地可部署模型；订单只能查询本人；模型不能直接退款；售后先生成待确认草稿；知识回答保留引用；提供源码和可复现测试证据。运行时完整提示词保存在 AiGateway.SYSTEM，不能用此归纳替代其精确版本。

## 开发与修复

1. 建立 Spring Boot/Spring AI/JDBC/Flyway 后端及 React 工作台，定义三类角色、订单、知识、工单、草稿和审计结构。
2. 完成业务状态机、事务、用户行锁、工单版本、幂等键与归属检查；测试覆盖越权、重复提交、过期草稿、非法流转和不可信引用。
3. 接入 Ollama 后发现 Windows 保留端口与只读权重挂载层级问题，改用 28434 和正确的 blobs/manifests 目录，不修改其他项目模型文件。
4. 前端初次构建发现退出登录处理器括号问题，修复后 TypeScript/Vite 构建通过；浏览器登录出现 Origin 拒绝，补齐 127.0.0.1/localhost 允许地址并在真实 HTTP 测试中验证可信/不可信 Origin。
5. 本地 Java 进程直接运行 target JAR 导致重打包文件被占用；改为开发运行副本，容器使用独立镜像层，后续 Maven verify 通过。
6. 真实模型初次验收全部通过但反复加载较慢；将对话和嵌入模型改为同时驻留，热请求多数降到约 1–2 秒，仍如实保留一次降级和长尾耗时。
7. 重建网页容器打断进行中的测试连接；检查运行记录等待后台任务结束，再串行重跑。不会把断线或 429 当作成功，也未删除中间失败摘要。
8. 服务重启后旧页面 CSRF 失效，登录/退出动作改为先刷新 token；不为业务写请求自动换键重试。补充前端字节流、错误与 CSRF 测试。
9. 执行 H2/PostgreSQL 双数据库测试、真实 HTTP、模型场景、浏览器、响应式布局、备份隔离恢复；整理部署、接口、演示、限制和依赖清单。
10. 新增纯 Java OrderLesson 与逐步阅读指南，以“项目实践”“AI 辅助”表述项目成果，不宣称已经部署指定服务器。
