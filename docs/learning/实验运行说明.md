# 可复现实验与验收命令

以下命令从项目根目录执行，Windows 使用 PowerShell。JDK 21、Node.js 24 是基础；中间件实验额外需要 Docker。测试环境中的账号/密码只用于回环地址上的虚构数据。

## 1. 纯 Java：先不启动任何服务

```powershell
java learning/FullstackBasics.java
java learning/ConcurrencyLab.java
```

前者检查订单归属、分页、record 相等性、泛型去重、异常；后者运行 40 个并发任务，断言最多同时执行 2 个、许可归还、超时后发出取消请求。把错误场景加进测试后再修改实现，不要只观察一行“运行成功”。

## 2. 基础自动测试

```powershell
.\backend\mvnw.cmd -B -ntp -f backend/pom.xml verify
npm.cmd ci --prefix frontend
npm.cmd test --prefix frontend
npm.cmd run build --prefix frontend
```

默认不连接 Redis、RabbitMQ 或真实模型。MiddlewareIntegrationTest 只有设置 MIDDLEWARE_TESTS=true 才执行，其余环境显示跳过属于显式条件，不算测试通过数量。

## 3. PostgreSQL、MySQL、Redis、RabbitMQ

```powershell
.\scripts\run-integration.ps1
```

该脚本启动独立的 `desk-fullstack-tests` Compose 项目，端口为 25432/23306/26379/25672，全部仅绑定 127.0.0.1；不挂载原演示库卷。先执行 PostgreSQL 加真实 Redis/RabbitMQ，再执行 MySQL 业务用例。中间件用例中的模型仍为 Mock。

运行结束保留测试服务，方便继续实验；需要释放资源时：

```powershell
docker compose -f compose.test-services.yaml stop
```

不要将 TEST_DATABASE_URL 指向真实业务库；启动测试会运行迁移与演示初始化。不要使用 `down -v` 清理原演示环境。

## 4. SQL 执行计划

```powershell
Get-Content learning/sql/postgres-index.sql -Raw | docker compose -f compose.test-services.yaml exec -T postgres psql -U desk_test -d desk_tests
Get-Content learning/sql/mysql-index.sql -Raw | docker compose -f compose.test-services.yaml exec -T -e MYSQL_PWD=test-only-password mysql mysql -u desk_test desk_tests
```

PostgreSQL 实验生成 50000 行临时数据；MySQL 生成 10000 行。对比 Seq/Table Scan 与 Index/Covering Index Lookup，以及排序和实际扫描行数。输出耗时受缓存和机器影响，不能拿这组数字当真实业务容量承诺。连接结束后临时表不保留。

练习：改变列的选择性、去掉联合索引的前导条件、把模糊搜索改成前缀匹配，重新看执行计划；不要仅背“索引一定更快”。

## 5. 真实浏览器测试

```powershell
npm.cmd exec --prefix frontend -- playwright install chromium
npm.cmd run test:e2e --prefix frontend
```

需先构建后端 JAR。脚本自动启动 21980 的内存 H2 后端和 21981 的 Vite，结束时停止子进程，不连接原演示库。覆盖分页/筛选、刷新和后退、角色页面与后端授权、创建表单、CSV 下载、异步任务提交。桌面与手机尺寸各执行一轮；不是实际手机或全浏览器兼容认证。

为了结果稳定，浏览器测试关闭模型与任务消费，只验证任务提交/状态显示；任务实际消费由后端及真实 RabbitMQ 测试验证。失败截图、trace 和报告放在 frontend/test-results、frontend/playwright-report，默认不提交 Git。

## 6. 可选中间件与 MySQL 演示

```powershell
# PostgreSQL + Redis + RabbitMQ；使用 .env 已配置的模型服务
.\scripts\start.ps1 -Middleware
# 新机器由本项目管理模型，支持 NVIDIA GPU 的环境可加 -Gpu
.\scripts\start.ps1 -ManagedModels -Middleware
# 独立 MySQL 数据卷与 19083 入口
.\scripts\start.ps1 -MySql -Middleware
# PostgreSQL 入口仍为 WEB_PORT，监控界面仅本机 19090
.\scripts\start.ps1 -Middleware -Observability
```

独立 MySQL 演示用于比较数据库行为，不会把原 PostgreSQL 数据自动迁移过去。模型仍需运行并下载指定权重；AI_ENABLED=false 只适用于手动业务与失败路径练习。

## 7. 真实 HTTP、真实模型与后台索引

```powershell
$env:BASE_URL='http://127.0.0.1:19082'
$env:EVIDENCE_DIR='.runtime/fullstack-http'
node scripts/http-acceptance.mjs
$env:EVIDENCE_DIR='.runtime/fullstack-live'
node scripts/live-acceptance.mjs
```

必须串行执行，同一客户不要同时在网页提问。脚本会创建演示工单/消息。真实模型冷启动较慢，结果要同时看行为断言、mode 和拒答情况；接口成功不能当作内容正确。

进入管理员知识页面点击“后台建立向量索引”，观察 PENDING → RUNNING → SUCCEEDED。模型不可用时观察 RETRY → FAILED；恢复模型后手动重试。记录任务 ID、attempts、indexed/total，而不是只截图一个成功提示。

## 8. 自己完成一次 Git 协作

```powershell
git switch -c practice/order-date-filter
git diff
# 完成功能、测试后，按文件暂存；不要提交 .env 或测试数据库
git add backend/src frontend/src
git diff --cached
git commit -m "Add order date filtering"
```

在分支上练习修改和测试，理解冲突内容后再解决；不要用强制覆盖绕过冲突。当前 GitHub CI 负责自动验证，不会自动部署到服务器。
